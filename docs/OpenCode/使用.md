# 使用

> 本文基于 OpenCode V2 官方文档（<https://opencode.ai/v2/docs/>）整理。配置文件保存后会自动热加载，一般无需重启。

OpenCode 采用**客户端-服务端架构**：TUI / CLI 等客户端连接到一个共享的后台服务（background service），由后台服务统一管理会话、配置、插件、权限与工具执行。客户端通常自动发现或启动该服务，仅在其异常时才需手动处理：

```bash
opencode service status     # 查看状态
opencode service restart    # 重启（仅在其卡死时使用，不要用重启来让配置生效）
```


## 一、终端界面 (TUI)

在项目目录中执行 `opencode` 即可进入全屏终端界面，输入需求回车即可。

```
cd ~/code/my-project
opencode
```

也可直接传入目录在别的项目中工作：

```bash
opencode ~/code/my-project
```

> 推荐使用支持 Truecolor 的终端以获得最准确的主题配色：Ghostty、WezTerm、Alacritty、Kitty。

### 1.1 基本交互

| 操作 | 按键 |
| :--- | :--- |
| 换行（不发送） | `Shift+Enter` / `Ctrl+Enter` / `Alt+Enter` / `Ctrl+J` |
| 工作中插入引导指令（steer） | `Enter` |
| 排队稍后执行的提示 | `Ctrl+X` 然后 `Enter` |
| 命令面板 | `Ctrl+P` |
| Leader 键（前缀键） | `Ctrl+X`（默认） |

### 1.2 引用文件上下文 (Context)

输入 `@` 可搜索并附加文件到提示中，可继续输入以缩小范围；还能在路径后指定行号或区间：

```
Review @src/auth.ts for error handling problems
Explain @src/auth.ts#20-45
```

### 1.3 Shell 模式

在空提示行首输入 `!` 进入 shell 模式，输入命令回车执行；按 `Esc` 退出而不执行。命令在会话工作目录中运行，输出保留在会话内：

```
!git status
```

### 1.4 斜杠命令 (Slash Commands)

输入 `/` 列出命令，继续输入可筛选，回车执行。常用命令：`/new`、`/sessions`、`/models`、`/agents`、`/undo`、`/redo`、`/editor`、`/mcps`、`/reload`、`/highlights`、`/btw`。

`/btw <问题>` 用于就当前对话快速提问，回答使用会话上下文与当前模型，但**不会加入对话**，因此不影响后续提示：

```
/btw 为什么第 2 步的测试失败了？
```

### 1.5 模型与智能体切换

| 操作 | 按键/命令 |
| :--- | :--- |
| 选择模型 | `Ctrl+X` 然后 `M`，或 `/models` |
| 循环最近使用的模型 | `F2` |
| 选择智能体 | `Ctrl+X` 然后 `A`，或 `/agents` |
| 循环智能体 | `Shift+Tab` |

### 1.6 会话 (Sessions) 与标签页 (Tabs)

| 操作 | 按键/命令 |
| :--- | :--- |
| 新建会话 | `Ctrl+X` 然后 `N` |
| 返回已有会话 | `Ctrl+X` 然后 `L`，或 `/sessions` |
| 最近会话与项目 | `Ctrl+O` |
| 切换标签页 | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| 关闭标签页 | `Ctrl+X` 然后 `W` |
| 恢复最近关闭的标签 | `Ctrl+Shift+T` |

标签页默认开启，可在 `cli.json` 的 `tabs` 中调整。

### 1.7 撤销 / 重做 (History)

- `/undo`（或 `Ctrl+X` 然后 `U`）：撤销最近一条用户消息及其后续工作，被撤销的提示会回到输入框供编辑。
- `/redo`（或 `Ctrl+X` 然后 `R`）：恢复被撤销的工作；若改为发送新提示则接受撤销结果并继续。

### 1.8 编辑器编辑提示

设置 `VISUAL` 或 `EDITOR` 后，按 `Ctrl+X` 然后 `E`（或 `/editor`）在外部编辑器中编辑当前提示，保存退出后文本回到输入框，再回车发送：

```bash
export EDITOR="nvim"
opencode
```


## 二、命令行 (CLI) 子命令

每个子命令都支持 `--help` 查看完整参数。部分服务端命令支持 `--standalone`（私有服务）或 `--server <url>`（指定服务）。

### 2.1 run —— 非交互运行

不打开界面，直接提交提示并打印回复，适合脚本与 CI：

```bash
opencode run "Explain this repository"
```

常用参数：

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"   # 指定模型
opencode run --continue "Now handle the expired case"                    # 继续上一会话
opencode run --format json "List the TODO comments"                      # 输出 NDJSON
opencode run --file src/server.ts --file src/client.ts "Review these"    # 附加文件
opencode run --agent build "Fix the failing test"                        # 指定智能体
opencode run --session ses_4f2a1c "Check edge cases"                     # 继续指定会话
opencode run --auto "Fix the failing test"                               # 自动放行未拒绝的权限
```

**CI 示例**（GitHub Actions）：

```yaml
name: OpenCode review
on: [pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install --global @opencode/cli
      - run: opencode run --standalone --model anthropic/claude-sonnet-5-5 "Review this repository for correctness and summarize any issues."
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

### 2.2 mini —— 精简交互界面

```bash
opencode mini
opencode mini --continue                                        # 继续上一会话
opencode mini --model anthropic/claude-sonnet-5-5 --prompt "..." # 指定模型与初始提示
opencode mini --session ses_4f2a1c                              # 继续指定会话
```

### 2.3 session —— 会话管理

```bash
opencode session list --max-count 20 --format json   # 列出（可限数量、转 JSON）
opencode session delete ses_9c1b08                   # 删除会话及其子会话
opencode session export ses_4f2a1c                   # 导出为 JSON
opencode session export ses_4f2a1c --sanitize        # 导出并脱敏
opencode session import session.json                 # 从 JSON 导入
opencode session import session.json --directory ~/code/project
```

### 2.4 auth —— 凭据管理

```bash
opencode auth list                       # 列出已配置的提供者与凭据
opencode auth login anthropic            # 登录某提供者
opencode auth login anthropic --method key   # 指定认证方式
opencode auth logout anthropic work      # 登出某账号
opencode auth switch anthropic work      # 切换激活账号
opencode auth export anthropic > credentials.json   # 导出（含密钥）
opencode auth import credentials.json   # 导入到另一台机器
```

### 2.5 models / mcp / plugin / stats

```bash
opencode models                         # 列出全部可用模型

opencode mcp list                       # 查看 MCP 服务器与连接状态
opencode mcp add context7 --url https://mcp.context7.com/mcp                       # 添加远程服务器
opencode mcp add everything --global -- npx -y @modelcontextprotocol/server-everything  # 添加本地服务器（全局）
opencode mcp add everything --env LOG_LEVEL=debug -- npx -y @modelcontextprotocol/server-everything
opencode mcp add context7 --url https://mcp.context7.com/mcp --header CONTEXT7_API_KEY=secret
opencode mcp auth sentry                # 对支持 OAuth 的远程服务器发起认证
opencode mcp logout sentry              # 清除已存储的 OAuth 凭据

opencode plugin list                    # 列出插件（--builtin 含内置）
opencode plugin add @example/opencode-tui   # 安装并加入全局配置
opencode plugin check                   # 检查更新
opencode plugin update                  # 更新
opencode plugin remove @example/opencode-tui

opencode stats                          # 用量统计
opencode stats --days 7 --models --cost # 近 7 天、按模型、含成本与 token
opencode stats --project .              # 仅当前项目
```

### 2.6 serve / pair —— 服务与配对

```bash
opencode serve                          # 启动 API 与 Web 服务
opencode serve --hostname 0.0.0.0 --port 4096
opencode serve --cors https://app.example.com   # 允许跨域来源

opencode pair                           # 打印一次性登录链接与二维码（5 分钟、单次有效）
opencode pair --url https://dev.example.com
opencode pair --remote                  # 经 OpenTunnel 远程配对（会暴露到公网，首次需确认）
opencode pair --remote --yes            # 脚本中跳过确认
```

### 2.7 service —— 后台服务管理

```bash
opencode service start / stop / restart / status
opencode service get hostname           # 读取某设置
opencode service set hostname 0.0.0.0   # 设置
opencode service set cors https://app.example.com
opencode service set env OPENCODE_LOG_LEVEL DEBUG   # 向服务进程注入环境变量
opencode service unset hostname         # 恢复默认
```

### 2.8 reload / api / acp / debug / upgrade / uninstall

```bash
opencode reload                         # 不重启服务即可重载配置（运行中的会话在下一步边界生效）

opencode api GET /api/session           # 以 HTTP 方法+路径调用本服务
opencode api session.list --param limit=10     # 以 OpenAPI operation ID 调用
opencode api session.create --data '{"title":"New session"}'
opencode api GET /api/session -H "accept: application/json"

opencode acp                            # 启动 ACP（Agent Client Protocol）服务，供编辑器集成

opencode debug agents                   # 列出智能体配置来源
opencode debug config                   # 列出配置来源
opencode debug heap-dump                # 写出后台服务堆快照并打印路径
opencode debug paths                    # 列出全局路径
opencode debug paths db                 # 打印单个路径（支持 db/home/data/config/cache/state/tmp/bin/log/repos）

opencode upgrade                        # 升级到最新版（别名 update）
opencode upgrade 2.0.21 --method bun    # 指定版本与包管理器

opencode uninstall --dry-run            # 预览将移除的内容
opencode uninstall                      # 停止服务并卸载（不删除会话数据、配置与状态）
```


## 三、项目配置 (opencode.jsonc)

OpenCode 服务端与项目配置使用 JSON / JSONC。务必带上 schema 以获得校验与补全：

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

> 注意：项目配置（`opencode.json(c)`）与终端客户端配置（`cli.json`）是**两套独立的配置**，不要把主题、快捷键等终端偏好放进 `opencode.json(c)`。

### 3.1 配置文件位置与优先级

从低到高合并（后发现的 `.opencode` 配置会覆盖所有直接配置）：

| 范围 | 路径 |
| :--- | :--- |
| 全局（用户） | `~/.config/opencode/opencode.json(c)` |
| 系统级（机器） | macOS: `/Library/Application Support/opencode`<br>Linux: `/etc/opencode`<br>Windows: `%ProgramData%\opencode` |
| 项目直接 | `<dir>/opencode.json(c)` |
| 项目 .opencode | `<dir>/.opencode/opencode.json(c)` |

OpenCode 从当前目录向上搜索到文件系统根：先合并各级直接的 `opencode.json(c)`（最远到最近），再同样顺序合并各级 `.opencode/opencode.json(c)`。系统配置优先级最高；MDM 托管配置（`ai.opencode.managed`）更高。

### 3.2 常用字段速览

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",   // 默认模型，provider/model 格式
  "default_agent": "build",                  // 默认智能体
  "shell": "/bin/zsh",                       // shell 工具使用的 shell
  "update": "notify",                        // disable / notify / auto
  "username": "alice",
  "snapshots": true,                         // 撤销/回滚所用的快照
  "formatter": true,                         // 写入后自动格式化
  "permissions": [ /* 见权限章节 */ ],
  "policies": [ /* 见策略章节 */ ],
  "agents": { /* 见智能体章节 */ },
  "commands": { /* 见自定义命令章节 */ },
  "skills": ["./team-skills"],
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
  "mcp": { "servers": { /* 见 MCP 章节 */ } },
  "providers": { /* 见模型章节 */ },
  "plugins": [ "opencode-example-plugin" ],
  "websearch": { "provider": "random" },
  "compaction": { "auto": true, "keep": { "tokens": 15000 }, "buffer": 20000 },
  "watcher": { "ignore": ["dist/**", "coverage/**"] },
  "media": { "image": { "auto_resize": true, "max_width": 2000, "max_height": 2000, "max_base64_bytes": 5242880 } },
  "tool_output": { "max_lines": 2000, "max_bytes": 51200 },
  "worktree": { "directory": "../worktrees" },
  "warming": { "prompt": "Do not perform any work. Reply with exactly: OK", "interval": "4 minutes", "duration": "30 minutes" }
}
```

### 3.3 变量替换

配置 JSON 字符串中可使用变量替换：

- 环境变量：`{env:VARIABLE_NAME}`（未设置则替换为空串）
- 文件内容：`{file:path/to/file}`（路径可相对配置文件、绝对、或 `~/` 开头）

```jsonc
{
  "providers": {
    "openai": { "settings": { "apiKey": "{file:~/.secrets/openai-key}" } }
  }
}
```

### 3.4 实验性功能 (experimental)

实验性设置可能随时变更或移除，慎用：

```jsonc
{
  "experimental": {
    "todo": true,                 // 给智能体 todowrite 工具跟踪多步任务
    "subagent_depth": 2,          // 子智能体可再起子智能体的深度，默认 1
    "background_compaction": true,// 后台生成压缩摘要，避免会话卡顿
    "image_generate": { "model": "openai/gpt-image-2" },
    "location_idle_timeout": "2 hours"  // 项目位置空闲多久后卸载，默认 60 分钟；false 为永不卸载
  }
}
```


## 四、智能体 (Agents)

智能体 = 系统提示 + 模型偏好 + 权限 + 展示信息的命名组合。

### 4.1 内置智能体

| 智能体 | 模式 | 用途 |
| :--- | :--- | :--- |
| **Build** (`build`) | `primary` | 默认编码智能体；工作区外默认允许，读取敏感 env 文件会询问 |
| **Plan** (`plan`) | `primary` | 探索与规划，不修改常规项目文件；可在要求时写计划文件，shell 仍受权限控制 |
| **General** (`general`) | `subagent` | 研究与多步任务，工具权限宽，但不能起子智能体 |
| **Explore** (`explore`) | `subagent` | 搜索/读取代码或网页，不修改文件 |

另有隐藏的 `compaction`、`title`、`summary` 智能体用于维护，不可直接选择。用相同 ID 可覆盖内置智能体。

### 4.2 模式 (mode)

| 模式 | 行为 |
| :--- | :--- |
| `primary` | 作为会话主智能体运行（新自定义智能体默认值） |
| `subagent` | 仅在子会话中通过 `subagent` 工具运行 |
| `all` | 两者皆可 |

子智能体在独立子会话中以全新上下文运行（前台或后台）。父智能体的 `subagent` 权限控制它能启动哪些子智能体；子智能体使用**自己**配置的权限。

### 4.3 自定义智能体

**Markdown 形式**（推荐目录式），存于 `~/.config/opencode/agents/<name>.md` 或 `.opencode/agents/<name>.md`，正文即 `system` 提示：

```md
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-5-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

嵌套路径会成为 ID 的一部分：`.opencode/agents/team/reviewer.md` → `team/reviewer`。

**JSONC 形式**，在配置文件 `agents` 下定义：

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" }
      ]
    }
  }
}
```

### 4.4 常用选项

| 字段 | 说明 |
| :--- | :--- |
| `description` | 用途描述（子智能体务必填写，会展示给选模型的模型） |
| `mode` | `primary` / `subagent` / `all` |
| `model` | `provider/model` 可带 `#variant`，或展开对象 `{providerID, model, variant}` |
| `system` | 系统提示（非空则替换该智能体的提供者基础提示；项目指令等仍会追加） |
| `permissions` | 有序规则列表 |
| `steps` | 正整数，最大模型步数；最后一步会移除工具并要求纯文本总结；新输入重置计数 |
| `hidden` | 从列表与发现中隐藏（控制可见性，非安全） |
| `color` | 六位十六进制 UI 颜色，如 `#ff6b6b` |
| `disabled` | 在该配置层级移除某内置/自定义智能体 |
| `request` | 每智能体的 header / body 覆盖（V2 暂未随请求发送，请求设置请配在 provider/model/variant） |

> 不要在新配置中使用 `temperature`、`top_p`、`prompt`、`permission`、`tools`、`disable`、`maxSteps` 等 V1 旧字段。


## 五、模型 (Models)

模型引用格式为 `provider/model`，可带 `#variant`，如 `openai/gpt-6.1-sol#high`。provider 在第一个 `/` 处结束且不含 `/` 或 `#`；model 可含 `/` 但不含 `#`；大小写敏感。

### 5.1 选择与默认

- 会话内切换：`/models` 或 `Ctrl+X`+`M`（仅当前会话，不改配置）
- 单次运行：`opencode run --model anthropic/claude-sonnet-5-5 "..."`
- 配置默认：

```jsonc
{ "model": "anthropic/claude-sonnet-5-5" }
```

> 会话已选模型优先于配置默认；切换会话模型不会回写配置文件；根级 `model` 不保留 `#variant`，变体请在会话/run/agent/command 中选。

### 5.2 变体 (variants)

变体是同一模型的命名选项（常用于推理强度/ token 预算）。可在 `variants` 数组中自定义，也可用 `capabilities.reasoning` 让 OpenCode 自动构建：

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": { "reasoningEffort": "medium" },
          "variants": [
            { "id": "fast", "settings": { "reasoningEffort": "low" } },
            { "id": "deep", "settings": { "reasoningEffort": "high", "reasoningSummary": "auto" } }
          ]
        }
      }
    }
  }
}
```

`capabilities.reasoning` 字段：`supported`（是否推理）、`toggle`（加 `none` 变体关闭推理）、`effort`（强度列表，`default` 不加变体）、`budget`（min/max 思考 token，`effort` 设了则忽略）。

### 5.3 模型选项与别名

provider/model 条目可定制 `settings`、`headers`、`body`，应用顺序为 provider → model → variant：

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "baseURL": "https://api.example.com/v1" },
      "headers": { "X-Team": "platform" },
      "models": {
        "gpt-6.1-sol": { "settings": { "reasoningEffort": "high" }, "body": { "store": false } }
      }
    }
  }
}
```

用 `modelID` 给 API 模型起友好目录 ID（`openai/coding-default` 可选，实际发送 `gpt-6.1-sol`）。对目录中不存在的模型，OpenCode 默认假设：支持工具、文本+图片输入、文本输出、200k 上下文、32k 输出——这些是**回退假设而非探测值**，请显式设置准确的 `capabilities` 与 `limit`。`disabled: true` 可隐藏模型。

### 5.4 兼容性 (compatibility)

`compatibility` 描述 API 的请求/响应差异，仅在该 API 读取时生效，其余字段被忽略：

| 字段 | 作用 | 默认 |
| :--- | :--- | :--- |
| `reasoningField` | 承载推理的 assistant 消息字段 | 流中观察到的字段，否则 `reasoning_content` |
| `requireReasoning` | 每条历史 assistant 消息都发推理字段 | 设了 `reasoningField` 或 DeepSeek 时默认 `true` |
| `maxTokensField` | 输出 token 上限的字段名 | 自动探测 `max_tokens`（DeepSeek/Moonshot/Together/Z.AI/Cerebras 等），否则 `max_completion_tokens` |
| `cacheFormat` | 提示缓存标记语法：`anthropic` / `alibaba` | provider 默认 |
| `streamUsage` | 是否请求流内 usage | `true` |
| `supportsPromptCacheKey` | 是否接受 `prompt_cache_key` | 视 provider |
| `supportsThinkingBlockBinding` | 让 API 丢弃上下文变化的 thinking block 而非报错 | 探测 Claude 5.1+ |
| `supportsEffortUpdates` | 以 per-message update 发送推理强度变化（保缓存） | 探测 Claude Opus 5 / 5.1+ / GPT-6+ |

Claude 经 OpenAI 兼容代理（如 LiteLLM）时，需显式设 `cacheFormat: "anthropic"`，否则 OpenCode 不知道要加 `cache_control` 断点。

### 5.5 本地模型

OpenCode 自动发现 Ollama、LM Studio、vLLM（默认本地地址）：

```
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

改地址或加认证时配置 `providers.<id>.settings.baseURL` 与 `apiKey`；用 `"plugins": ["-opencode.provider.ollama"]` 等可禁用发现。

任意 OpenAI 兼容服务器手动定义（须填真实模型名、上下文/输出上限、输入输出类型、是否支持工具，OpenCode 无法自动探测）：

```jsonc
{
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "http://127.0.0.1:1234/v1" },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": { "tools": true, "input": ["text"], "output": ["text"] },
          "limit": { "context": 32768, "output": 8192 }
        }
      }
    }
  }
}
```


## 六、工具 (Tools)

描述想要的结果，OpenCode 自行选择工具并在需要时请求批准。也可点名工具：

```
Find where request timeouts are configured, change the default to 30 seconds, and run the relevant existing tests.
Use grep to find every reference to DEFAULT_TIMEOUT, then read the matching files.
```

### 6.1 文件工具

| 工具 | 说明 | 权限 action |
| :--- | :--- | :--- |
| `read` | 读取文件或非递归目录列表；文本带行号，每页 ≤2000 行、50KiB；支持 PNG/JPEG/GIF/WebP/PDF（≤20MiB） | `read`（资源为归一化路径） |
| `glob` | 按 glob 模式找文件路径，默认限 100 个、超时 30s | `glob`（资源为模式） |
| `grep` | 按正则/字面量搜索文件内容，返回路径/行号/预览，默认限 100 行 | `grep`（资源为**模式**而非搜索路径） |
| `edit` | 替换现有文件中文本，`oldString` 须精确匹配一次（除非 `replaceAll`） | `edit` |
| `write` | 创建或完全替换文本文件，自动建父目录 | `edit` |
| `patch` | 一次补丁可增/改/移/删多文件（`*** Add/Update/Delete File` 段）；仅支持 GPT 模型，其余用 `edit`/`write` | `edit`（每个受影响路径） |

工作区/项目 worktree 之外的路径还会检查 `external_directory`（默认允许）。

### 6.2 命令工具

`shell` 在用户 shell 中执行命令。用 `workdir` 而非 `cd`，用 `timeout`(ms) 调整默认 2 分钟前台超时；`background: true` 用于长驻进程（立即返回，完成时通知，默认无超时）。**shell 拥有宿主用户的文件系统/进程/网络权限，请用窄规则授权。**

### 6.3 Web 工具

- `webfetch`：取一个 HTTP/HTTPS URL 为 markdown(默认)/text/html，`timeout` ≤120s；接受文本响应，不接受二进制
- `websearch`：搜索所选集成以获取当前信息

### 6.4 交互工具

- `question`：暂停并向用户提问，每题有 header、prompt、choices；`multiple` 允许多选；自由作答始终可用
- `skill`：加载某可用 skill 的指令与资源到对话

### 6.5 自动化工具

- `subagent`：启动配置好的子智能体子会话；前台等待结果，`background: true` 立即返回；用返回的 `sessionID` 可继续同一子会话；默认嵌套深度 1
- `execute`（Code Mode）：在受限 JS 运行时中调用并组合目录内工具，便于并行独立调用与处理中间结果；运行时无直接文件系统/imports/timers，提供 `fetch`；拒绝 `execute`(`*`) 会移除 Code Mode 及仅经其到达的工具（默认 MCP 工具也经此）

Code Mode 的 `opencode` 命名空间还含会话工具（`session_rename`、`session_move`）与 worktree 工具（`worktree_create`、`worktree_list`、`worktree_remove`）；桌面应用还提供 `browser` 命名空间控制浏览器标签页。


## 七、权限 (Permissions)

权限决定智能体能否对某资源执行某动作。

### 7.1 规则

每条规则三字段：`action`（工具/权限动作，支持通配）、`resource`（路径/命令/URL/查询/skill ID/agent ID 等，支持通配）、`effect`（`allow`/`deny`/`ask`）。**最后匹配的规则生效**，无匹配则 `ask`。

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" }
  ]
}
```

通配：`*` 匹配零或多个字符（含 `/`），`?` 匹配一个字符。以 ` *` 结尾的 shell 模式也匹配不带参数的命令（`git status *` 同时匹配 `git status` 与 `git status --short`）。

多资源操作（如多文件 patch）：任一 `deny` 即拒绝；否则任一 `ask` 即询问；否则允许。规则按顺序合并：低优先级配置先加载，全局规则次之，智能体规则最后追加。

### 7.2 内置动作

| Action | 资源 |
| :--- | :--- |
| `read` | 位置相对内部路径或规范化绝对外部路径 |
| `edit` | `edit`/`write`/`patch` 目标路径 |
| `glob` / `grep` | 请求的模式 / 正则（非搜索路径） |
| `shell` | 扫描器产出的命令串；复合命令可能产出多条 |
| `subagent` | 目标智能体 ID |
| `skill` | skill ID |
| `question` | `*` |
| `webfetch` / `websearch` | URL / 查询 |
| `external_directory` | 规范化外部目录边界，通常以 `/*` 结尾 |
| `<server>_<tool>` | MCP 工具，`*` |
| `opencode_list_mcp_resources` / `opencode_read_mcp_resource` | 服务器名 / `<server>:<uri>` |
| `experimental_image_generate` | 选中图片模型 `providerID/modelID`（可带 `#variant`） |
| `execute` | `*`；deny 会移除 Code Mode 及仅经其到达的工具 |

### 7.3 默认策略

每个智能体（含自定义）起始基础策略：

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" }
]
```

各内置智能体在此之上追加策略（如 `plan` 拒绝除 `~/.opencode/plan` 外的编辑；`explore` 拒绝除 shell/读/glob/grep/web/external_directory 外的一切）。由于默认不询问 `external_directory`，工作区外读写不弹窗——如需提示或禁止外部访问，请加 `external_directory` 的 `ask`/`deny` 规则。

### 7.4 审批与策略

规则判为 `ask` 时，客户端可选：`once`（仅本次）、`always`（保存为项目级持久 `allow` 规则）、`reject`（拒绝本次及该会话其他待批请求）。保存的审批不会覆盖配置的 `deny`。

**策略 (policies)** 可在规则与审批之后**硬拒绝**（把 `allow`/`ask` 变 `deny`，从不授权）：

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }
  ]
}
```

全局与 Console 托管策略优先于项目配置——组织可借此封禁某仓库本会允许的命令。

### 7.5 智能体级权限

共享规则放顶层，窄规则放 `agents.<id>.permissions`（追加在全局规则之后，不替换）：

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" }
  ],
  "agents": {
    "reviewer": {
      "mode": "subagent",
      "permissions": [ { "action": "edit", "resource": "*", "effect": "deny" } ]
    }
  }
}
```


## 八、自定义命令 (Commands)

把常用提示做成 `/xxx` 斜杠命令。

### 8.1 Markdown 形式

全局 `~/.config/opencode/commands/`，项目 `.opencode/commands/`，仅发现 `.md`。嵌套路径用 `/` 分隔：

```md title=".opencode/commands/team/review.md"
Review $ARGUMENTS using the team's checklist.
```

→ `/team/review src/auth.ts`

带 frontmatter 时：

```md title=".opencode/commands/review.md"
---
description: Review code for correctness
agent: plan
model: anthropic/claude-sonnet-5-5#high
---

Review $ARGUMENTS. Report bugs first.
```

### 8.2 JSON 形式

```jsonc
{
  "commands": {
    "audit": {
      "template": "Audit $ARGUMENTS.",
      "description": "Audit a package",
      "agent": "general",
      "model": "anthropic/claude-sonnet-5-5#high",
      "subagent": true
    }
  }
}
```

### 8.3 参数

| 占位符 | 含义 |
| :--- | :--- |
| `$ARGUMENTS` | 完整参数串原样代入 |
| `$1`、`$2` … | 解析的位置参数（引号分组并被移除）；最高编号占位符吞掉其后所有内容；缺失位置为空串 |
| 无占位符 | 非空参数会追加在模板后空一行 |

**Shell 注入**：`` !`命令` `` 会在提交前执行并把输出插入（参数占位符先展开）；⚠️ shell 块在智能体权限流之外执行，仅用可信来源的命令，**勿把不可信参数放进 shell 块**。

### 8.4 执行与模型选择

命令默认在当前会话运行。模型选择优先级：命令 `model` > 命令 agent 的配置模型 > 当前会话模型。`subagent: true` 在后台子会话运行（父会话保持可用，子完成时回传结果）。

> 保存命令文件会自动重载，无需重启。项目源优先于全局源；同名命令后者替换前者。`@path` 在模板中**不会**展开，附件请在调用时通过输入框附加。


## 九、技能 (Skills)

技能给智能体**可复用的任务指令**（不是新工具）。在 `.opencode/skills/<skill-id>/SKILL.md` 中用 `description` 描述何时使用：

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow
1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

相关脚本/参考/模板可放在 `SKILL.md` 同目录，技能内写的路径相对于含 `SKILL.md` 的目录。

### 9.1 发现位置

| 范围 | 来源 |
| :--- | :--- |
| 全局 | `~/.config/opencode/skills` |
| 全局兼容 | `~/.claude/skills`、`~/.agents/skills` |
| 项目 | `.opencode/skills` |
| 项目兼容 | `.claude/skills`、`.agents/skills` |

项目源从当前目录向上到项目根逐级搜索。支持两种形式：源根的 `*.md`（如 `skills/review.md`），或 `SKILL.md` 嵌套在分组目录（如 `skills/git-release/SKILL.md`）；含 `SKILL.md` 的目录是单个技能，不再向内搜索。

可用 `skills` 数组追加本地目录或 HTTP 目录；HTTP 目录需 `index.json` 描述（含 `name`/`version`/`files`，路径须安全相对同源，含 `SKILL.md` 或 `<name>.md`，改文件要升 `version` 刷新缓存）。

### 9.2 ID 与 frontmatter

ID 由文件路径决定（frontmatter `name` 仅显示用）：

| 文件 | ID |
| :--- | :--- |
| `<source>/git-release.md` | `git-release` |
| `<source>/git-release/SKILL.md` | `git-release` |
| `<source>/teams/release/SKILL.md` | `release` |

frontmatter 可选：`name`（显示名）、`description`（供模型发现的摘要）、`metadata.opencode/autoinvoke: false`（从模型可用列表隐藏，但可按 ID 显式加载）。**无 description 的技能不会被模型发现。**

### 9.3 优先级与加载

同 ID 后注册的源覆盖先注册的。源注册顺序（低→高）：内置 → `.claude/skills`（全局再到祖先→当前）→ `.agents/skills`（同）→ `~/.config/opencode/skills` → 项目 `.opencode/skills`（项目根→当前）→ 显式 `skills` 配置项。

每个模型步列出有 description 且未 `autoinvoke:false` 的技能（仅 ID/name/description）；模型用 `skill` 工具按精确 ID 加载正文。用户也可在提示中 `@skill-id` 显式加载。支持文件内容**不自动**加载，须技能指示读取。

### 9.4 权限

用 `skill` action、skill ID 作 resource：

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" }
  ]
}
```


## 十、MCP 服务器

OpenCode 连接 [MCP](https://modelcontextprotocol.io/) 服务器以扩展工具、提示、资源、指令。MCP 工具会消耗模型上下文，**只加需要的服务器**。

### 10.1 添加

远程服务器（Streamable HTTP，须绝对 URL）：

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp add context7 --global --url https://mcp.context7.com/mcp   # 全局
opencode mcp list
```

远程默认用 OAuth；若 `mcp list` 显示 `needs authentication`，在 OpenCode 中 `/mcps` 选择该服务器登录。

本地服务器（MCP stdio，`--` 后接命令）：

```sh
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything
opencode mcp add everything --env LOG_LEVEL=debug -- npx -y @modelcontextprotocol/server-everything
```

### 10.2 手写配置

V2 服务器名放在 `mcp.servers` 下（不是直接放 `mcp` 下）：

```jsonc
{
  "mcp": {
    "timeout": { "startup": 45000, "catalog": 30000, "execution": 600000 },
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "cwd": ".",
        "environment": { "LOG_LEVEL": "info", "MCP_API_KEY": "{env:MCP_API_KEY}" },
        "disabled": false,
        "codemode": true,
        "timeout": { "catalog": 60000 }
      },
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "headers": { "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}" },
        "oauth": false
      }
    }
  }
}
```

本地字段：`type:"local"`、`command`（必填）、`cwd`、`environment`、`disabled`、`codemode`、`timeout`、`protocol`。
远程字段：`type:"remote"`、`url`（必填）、`headers`、`oauth`、`disabled`、`codemode`、`timeout`、`protocol`。
超时默认：`startup` 30s、`catalog` 30s、`execution` 12h。
`protocol`：`legacy`（默认，`initialize` 握手，≤2025-11-25）、`auto`（探测 2026-07-28 回退）、`2026-07-28`（要求该版本）。

### 10.3 OAuth

未设 `oauth:false` 时默认启用 OAuth（PKCE，自动刷新，凭据存于配置之外）。多数服务器只需 URL；需认证时 `/mcps` 选择登录，或 `opencode mcp auth <name>`。

客户端注册按优先级：预注册 client（`oauth.client_id`）→ CIMD（Client ID Metadata Document，需服务器支持且未设 `redirect_uri`）→ DCR（动态注册）。预注册字段用 snake_case：`client_id`、`client_secret`、`scope`、`callback_port`、`redirect_uri`、`auth_server_metadata_url`。清除凭据用 `opencode mcp logout <name>`。

### 10.4 命名与权限

工具命名为 `<server>_<tool>`（非字母数字 `_` `-` 的字符替换为 `_`）。MCP prompt 变为 `<server>:<prompt>` 命令。默认经 Code Mode 暴露（按规范化的服务器名分组）；`codemode:false` 则直接列入提供者原生工具列表。

用权限隐藏/拒绝工具而不断开服务器：

```jsonc
{ "permissions": [ { "action": "context7_*", "resource": "*", "effect": "deny" } ] }
```

资源经 `opencode_list_mcp_resources` / `opencode_read_mcp_resource` 两内置工具读取，权限 resource 分别为服务器名与 `<server>:<uri>`。服务器初始化返回的指令会加入系统提示（除非该服务器所有工具被 deny，或 Code Mode 下 `execute` 被 deny）。


## 十一、项目指令 (AGENTS.md)

在仓库放 `AGENTS.md` 给 OpenCode 持久的项目指引（构建命令、架构、约定、验证要求等），**提交到仓库**让所有人获得相同指引：

```md title="AGENTS.md"
# Project instructions
- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

### 11.1 作用域与加载顺序

`AGENTS.md` 放在其指引应生效的目录。OpenCode 先加载全局文件，再从当前工作区目录向家目录加载各级 `AGENTS.md`（工作区在项目外时只加载全局）。组合顺序：

```
1. Agent 或 provider 系统提示
2. Code Mode 工具指引（启用时）
3. MCP 服务器、reference、skill 指引
4. 全局与项目 AGENTS.md，再配置的 instructions
5. 内置日期与环境上下文
6. 会话级指令
```

> V2 **只识别 `AGENTS.md`**，不以 `CLAUDE.md` 为回退。设 `OPENCODE_DISABLE_PROJECT_CONFIG=1` 可跳过项目 `AGENTS.md` 发现（不禁用全局）。

### 11.2 嵌套发现与更新

工作区下方的 `AGENTS.md` 在智能体探索时按最近优先加载并去重（保持在模型可见历史内）。编辑全局或上层 `AGENTS.md` 会在下次模型请求前检测变更并注入指令更新；删除所有环境 `AGENTS.md` 则告知会话旧指令不再适用。

### 11.3 配置额外指令

`instructions` 数组可加文件、glob、HTTP(S) URL，在 `AGENTS.md` 之后按列出顺序加载：

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md", "~/rules/opencode.md", "https://example.com/instructions.md"]
}
```


## 十二、终端客户端配置 (cli.json)

终端偏好独立于服务端/项目配置，存于全局 `~/.config/opencode/cli.json`（或 `$XDG_CONFIG_HOME/opencode/cli.json`），**无项目级 CLI 配置**。可设 `OPENCODE_CLI_CONFIG_CONTENT` 以内联 JSON 覆盖合并。多数设置也可在 TUI 中 `Ctrl+P` → Open settings 调整。

```json title="cli.json"
{ "$schema": "https://opencode.ai/v2/cli.json" }
```

### 12.1 外观与输入

```json title="cli.json"
{
  "theme": { "name": "tokyonight", "mode": "system" },
  "animations": true,
  "cursor": { "style": "block", "blinking": true },
  "mouse": true,
  "scroll": { "speed": 3, "acceleration": false },
  "prompt": { "editor": true, "paste": "compact", "image_preview": false }
}
```

`theme.mode`：`system`/`dark`/`light`；`cursor.style`：`block`/`underline`/`line`/`default`；`prompt.paste`：`compact`/`full`。

### 12.2 会话与标签页

```json title="cli.json"
{
  "session": {
```

## 十三、排错 (Troubleshooting)

OpenCode 是客户端+后台服务。先判断问题属于客户端、共享服务还是某项目：

```bash
opencode service status                 # 检查服务
opencode api get /api/info              # 验证 API
opencode --standalone                   # 用私有服务运行 TUI 以隔离共享服务问题
```

日志位于 `~/.local/share/opencode/log/opencode.log`，过滤 `role=cli`（客户端启动）与 `role=server`（会话/提供者/插件/权限/工具）。需要更详细日志时单次运行 `OPENCODE_LOG_LEVEL=DEBUG`。

- 排错时**不要**删除或编辑数据库、服务注册或服务配置；用外部工具检查持久数据前先备份。
- 分享诊断前**脱敏** API key、授权头、提示、文件内容等敏感数据。
- 配置变更会自动热加载；强制完整重载用 `/reload` 或 `opencode reload`。
