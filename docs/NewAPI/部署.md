# 部署

> 本文整理自 New API 官方 [安装文档](https://docs.newapi.ai/zh/docs/installation)。最常用的方式是 Docker。

## 系统要求

*   **数据库**（三选一）：
    *   **SQLite**（默认，开箱即用，适合测试/轻量）
    *   **MySQL ≥ 5.7.8**
    *   **PostgreSQL ≥ 9.6**（生产推荐）
*   **缓存**（可选）：Redis + 内存缓存
*   **容器平台**：Linux amd64 / arm64
*   **独立日志库**（可选）：`LOG_SQL_DSN` 支持分离日志库，亦支持 ClickHouse

## Docker 快速开始（SQLite）

最快上手方式，单容器 + SQLite：

```bash
mkdir -p data
docker run --name new-api -d --restart unless-stopped \
  -p 127.0.0.1:3000:3000 \
  -e TZ=Asia/Shanghai \
  -v "$(pwd)/data:/data" \
  calciumion/new-api:latest
```

*   默认**端口 3000**；SQLite 数据存在挂载的 `data` 目录。
*   浏览器打开 <http://localhost:3000>，进入**初始化向导**手动创建管理员账号与密码（仅首次安装需要）。

> 镜像名仍是 `calciumion/new-api`（Docker Hub 沿用旧组织名；GitHub 仓库已迁至 `QuantumNous/new-api`）。

## Docker + PostgreSQL（生产推荐）

```bash
docker run --name new-api -d --restart always \
  -p 3000:3000 \
  -e SQL_DSN="postgresql://用户名:密码@数据库地址:5432/数据库名" \
  -e TZ=Asia/Shanghai \
  -v /your/data/path:/data \
  calciumion/new-api:latest
```

## Docker + MySQL

```bash
docker run --name new-api -d --restart always \
  -p 3000:3000 \
  -e SQL_DSN="用户名:密码@tcp(数据库地址:3306)/数据库名" \
  -e TZ=Asia/Shanghai \
  -v /your/data/path:/data \
  calciumion/new-api:latest
```

## Docker Compose（推荐：New API + PostgreSQL + Redis）

```yaml
version: '3.4'
services:
  new-api:
    image: calciumion/new-api:latest
    container_name: new-api
    restart: always
    command: --log-dir /app/logs
    ports:
      - '3000:3000'
    volumes:
      - ./data:/data
      - ./logs:/app/logs
    environment:
      - SQL_DSN=postgresql://root:123456@postgres:5432/new-api   # ⚠️ 改密码
      # - SQL_DSN=root:123456@tcp(mysql:3306)/new-api            # MySQL 备选
      - REDIS_CONN_STRING=redis://redis
      - TZ=Asia/Shanghai
      - ERROR_LOG_ENABLED=true
      - BATCH_UPDATE_ENABLED=true
    depends_on:
      - redis
      - postgres
    healthcheck:
      test: ['CMD-SHELL', "wget -q -O - http://localhost:3000/api/status | grep -o '\"success\":\\s*true' || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 3

  redis:
    image: redis:latest
    container_name: redis
    restart: always

  postgres:
    image: postgres:15
    container_name: postgres
    restart: always
    environment:
      POSTGRES_USER: root
      POSTGRES_PASSWORD: 123456   # ⚠️ 改密码
      POSTGRES_DB: new-api
    volumes:
      - pg_data:/var/lib/postgresql/data

volumes:
  pg_data:
```

部署步骤：

```bash
git clone https://github.com/QuantumNous/new-api.git
cd new-api
# 编辑 docker-compose.yml：改密码，建议设置 SESSION_SECRET（openssl rand -hex 32）
docker compose up -d
docker compose logs -f new-api
```

## 关键环境变量

| 变量 | 用途 | 默认 |
| :--- | :--- | :--- |
| `PORT` | 服务监听端口 | `3000` |
| `SQL_DSN` | 数据库连接串（不设则用 SQLite） | SQLite（`one-api.db`） |
| `LOG_SQL_DSN` | 独立日志库连接串 | — |
| `REDIS_CONN_STRING` | Redis 连接 | — |
| `SESSION_SECRET` | 持久化认证密钥（多节点必须一致） | — |
| `CRYPTO_SECRET` | 缓存 HMAC 密钥（默认同 SESSION_SECRET） | — |
| `TZ` | 时区 | — |
| `MEMORY_CACHE_ENABLED` | 启用内存缓存 | `false` |
| `GENERATE_DEFAULT_TOKEN` | 新用户自动创建令牌 | `false` |
| `SESSION_COOKIE_SECURE` | HTTPS 控制台设 `true` | — |
| `SESSION_COOKIE_TRUSTED_URL` | 受信 HTTPS 来源（需 Secure 模式） | — |
| `TRUSTED_PROXIES` | 受信反向代理 IP/CIDR | — |
| `STREAMING_TIMEOUT` | 流式响应超时（秒） | `300` |
| `RELAY_TIMEOUT` | 中继请求超时（秒，0=不限） | `0` |
| `CHANNEL_UPDATE_FREQUENCY` | 自动更新渠道余额（分钟） | — |
| `CHANNEL_TEST_FREQUENCY` | 自动渠道测试（分钟） | — |
| `NODE_TYPE` | 节点类型 `master`/`slave` | `master` |
| `SYNC_FREQUENCY` | 缓存同步频率（秒） | `60` |
| `GLOBAL_API_RATE_LIMIT` | 全局 API 限速（每 IP） | `180` |
| `FORCE_STREAM_OPTION` | 强制 stream_options 以取用量信息 | `true` |
| `AZURE_DEFAULT_API_VERSION` | Azure 默认 API 版本 | `2025-04-01-preview` |

完整列表见 [环境变量文档](https://docs.newapi.ai/zh/docs/installation/config-maintenance/environment-variables)。

## 上手配置

部署完成后，在 Web 控制台（<http://服务器IP:3000>）完成核心配置：

### 1. 添加渠道（上游提供者）

控制台 → **渠道** → **添加渠道**：

*   **渠道类型**：选提供者（OpenAI / Anthropic / Gemini / 通义 / DeepSeek 等）
*   **API Key**：填上游提供者的真实密钥
*   **可用模型**：该渠道服务的模型列表
*   **分组**：分组归属（渠道与令牌须同分组才能互通）
*   **权重 / 优先级**：用于加权随机负载均衡与故障转移

填完可运行**渠道测试**验证连通性。高级用法支持**参数覆盖**（简单模式与高级操作模式：set/delete/move/append/prepend/copy/trim/replace/regex_replace，可带条件逻辑）动态修改请求参数。

### 2. 创建令牌（下游密钥）

控制台 → **令牌** → **添加令牌**：

*   令牌名称
*   **可用额度**：用量上限
*   **过期时间**：可选
*   **模型范围**：限制该令牌可调用的模型（令牌级模型访问控制）
*   **IP 限制**：可选
*   **分组**：须与渠道分组匹配

生成的令牌（格式 `sk-...`）就是客户端使用的 API Key。

### 3. 客户端对接

把客户端的 Base URL 指向 New API，用令牌作为 API Key：

| 客户端协议 | Base URL |
| :--- | :--- |
| OpenAI 兼容 | `http://your-server:3000/v1` |
| Anthropic Messages | `http://your-server:3000`（端点 `/v1/messages`） |
| Gemini | `http://your-server:3000/v1beta` |

**对接 Claude Code**：设置环境变量 `ANTHROPIC_BASE_URL` 指向 New API，用令牌作 Anthropic API Key。官方提供辅助脚本：`https://raw.githubusercontent.com/QuantumNous/new-api-docs/refs/heads/main/helper/claude-cli-setup.sh`（Linux/Mac）与 `.ps1`（Windows）。

**对接 OpenCode**：在 `opencode.json` 的 provider 里把 `baseURL` 指向 `http://your-server:3000/v1`，`apiKey` 填 New API 令牌即可（New API 完全兼容 OpenAI 协议）。

## 运维

*   **多节点部署**：`NODE_TYPE=slave` 的从节点须与主节点使用相同的 `SESSION_SECRET`；缓存经 Redis 或定时同步（`SYNC_FREQUENCY`）保持一致。
*   **反向代理**：置于 Nginx/Caddy 之后时，用 `TRUSTED_PROXIES` 指定可信代理 IP/CIDR，并设 `SESSION_COOKIE_SECURE=true`（HTTPS）。
*   **渠道健康**：`CHANNEL_TEST_FREQUENCY` 定时自动测试渠道；`CHANNEL_UPDATE_FREQUENCY` 定时更新渠道余额。
*   **备份**：定期备份 `data/` 目录（SQLite）或数据库（MySQL/PostgreSQL）。
