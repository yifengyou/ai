# AI 安全

### 1. Bubblewrap (`bwrap`)

**定位**：轻量级、用户空间的沙箱工具。

**核心功能与架构**：
- **技术基础**：完全基于 Linux 内核原生机制，包括 **User Namespaces**、**Mount Namespaces**、**PID Namespaces**、**Network Namespaces**、**Capabilities** 和 **Seccomp-BPF**。
- **工作模式**：通过命令行参数动态构建一个隔离的文件系统视图，并限制进程的系统调用和权限。它本身不提供默认的安全策略，安全性完全取决于用户传入的参数。
- **启动速度**：极快（微秒到毫秒级），因为没有虚拟化开销。
- **资源占用**：非常低，仅需少量内存和CPU。
- **隔离级别**：**操作系统级隔离**。虽然强大，但共享同一个内核，存在内核漏洞被利用导致逃逸的风险。

**典型应用场景**：
- Flatpak 应用的运行时隔离。
- 在 CI/CD 环境中安全地运行不可信的构建脚本。
- 为桌面应用提供简单的沙箱环境。

---

### 2. Firecracker

**定位**：由 AWS 开源的、专为 Serverless/FaaS 场景设计的轻量级 VMM (Virtual Machine Monitor)。

**核心功能与架构**：
- **技术基础**：基于 Linux 的 **KVM (Kernel-based Virtual Machine)**，创建硬件级隔离的 **MicroVMs**。
- **工作模式**：每个 MicroVM 都是一个独立的、精简的虚拟机，拥有自己的内核和用户空间。Firecracker 通过裁剪设备模型（只支持5种 VirtIO 设备）来实现极致的轻量化。
- **启动速度**：极快（通常在 125ms 以内），远超传统虚拟机。
- **资源占用**：低至 5MB 内存 overhead，非常适合高密度部署。
- **隔离级别**：**硬件级隔离**。这是最强的隔离形式之一，即使 Guest OS 内核被攻破，也很难影响到 Host OS 或其他 MicroVM。

**典型应用场景**：
- AWS Lambda 和 Fargate 的底层运行时。
- 需要强隔离、高安全性和快速启动的 Serverless 平台。
- 多租户环境中运行不可信代码。

---

### 3. Sandlock

**定位**：一个新兴的、针对 **AI Agent** 场景优化的轻量级沙箱方案。

**核心功能与架构**（基于现有资料推断）：
- **设计理念**：挑战了“AI Agent = 恶意攻击者”的传统安全假设。认为 AI Agent 通常是善意的，但会犯错（如误删文件、无限循环）。因此，其安全模型更侧重于 **权限最小化** 和 **操作审计**，而非构建坚不可摧的“监狱”。
- **技术基础**：虽然具体实现细节未完全公开，但从描述看，它很可能也是基于 Linux 内核的命名空间和 Seccomp 等机制，但进行了高度定制化，以移除不必要的复杂性（如 root 权限）。
- **关键特点**：
  - **无 Root 权限**：Agent 默认在无特权环境下运行，从根本上杜绝了提权风险。
  - **轻量级**：旨在比 Firecracker 和 gVisor 等方案更轻、更快。
  - **场景驱动**：专为 AI Agent 常见的操作（如文件读写、网络请求、代码执行）设计，而非通用计算。
- **隔离级别**：推测为 **增强的操作系统级隔离**，但通过严格的权限控制来弥补与硬件隔离的差距。

**典型应用场景**：
- 在本地或云端安全地运行 AI Agent，执行用户委托的任务。
- 需要平衡安全性、性能和开发便捷性的 AI 应用平台。

### 详细对比总结

| 特性 | **Bubblewrap** | **Firecracker** | **Sandlock** |
| :--- | :--- | :--- | :--- |
| **隔离类型** | OS Namespace / Cgroups | 硬件虚拟化 (MicroVM) | 定制化 OS Namespace + 权限控制 |
| **安全模型** | 用户定义策略，灵活性高 | “监狱”模型，防御主动攻击者 | “防呆”模型，防御意外错误 |
| **启动速度** | 极快 (μs-ms) | 快 (≈125ms) | 极快 (推测) |
| **资源开销** | 极低 | 低 (≈5MB overhead) | 极低 (推测) |
| **内核共享** | 是 | 否 (每个 VM 独立内核) | 是 |
| **逃逸风险** | 中 (依赖内核安全) | 极低 (硬件隔离) | 中低 (依赖权限控制) |
| **主要优势** | 轻量、简单、集成方便 | 强隔离、高安全性、高密度 | 针对 AI Agent 场景优化、无 root 更安全 |
| **主要劣势** | 配置复杂，策略需自行设计 | 启动仍慢于容器，架构重 | 新兴项目，生态和文档可能不成熟 |
| **适用场景** | 桌面应用、CI/CD、轻量隔离 | Serverless、多租户、高安全需求 | AI Agent 执行环境 |

### 结论

- 如果你需要**最强的、硬件级别的隔离**来运行完全不可信的代码（例如公有云 FaaS），**Firecracker** 是最佳选择。
- 如果你需要一个**轻量、灵活、易于集成**的沙箱来隔离已知应用或脚本，**Bubblewrap** 是一个成熟可靠的工具。
- 如果你正在构建一个 **AI Agent 平台**，并且相信 Agent 本身是善意的，只是需要防止其犯错，那么 **Sandlock** 所倡导的“轻量级、无 root、权限最小化”的理念可能提供了一个更优雅、高效的解决方案。不过，在采用 Sandlock 之前，应仔细评估其开源状态、社区支持和长期维护能力。
